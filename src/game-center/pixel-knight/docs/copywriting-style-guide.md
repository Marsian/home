# Pixel Knight 文案风格约定

## 目标
- 风格保持简单、朴素、清晰。
- 让玩家“一眼看懂”，不靠堆砌华丽词藻。

## 基本原则
- 优先说明功能和结果，再补充氛围。
- 用短句，避免连续修饰词。
- 同一概念只用一种叫法（例如“护甲”不要在别处写成“防御”）。
- 数值描述直给：`攻击 +12`、`冷却 3.2 秒`。

## 禁止项
- 避免过度史诗化词汇：例如“神圣、辉芒、赐福、刻印”连续叠加。
- 避免名字过长（建议 4-8 个汉字）。
- 避免描述里同时出现多个意象（风、光、圣殿、传说等）导致信息噪音。

## 命名模板
- 技能名：`动作 + 对象`（例：`旋风斩`、`盾击`）。
- 装备名：`材质/类型 + 部位`（例：`布帽`、`木盾`、`铁剑`）。
- 词条描述：`触发条件 + 实际效果`（例：`盾击命中后，额外造成一次小范围伤害。`）。

## 文案检查清单
- 玩家第一次看到能否立刻懂？
- 这句话删掉修饰词后是否仍完整？
- 是否和已有术语保持一致？
- 是否能映射到真实机制（可被验证）？
