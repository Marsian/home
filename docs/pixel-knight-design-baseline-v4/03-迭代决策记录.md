# 迭代决策记录

日期：2026-04-28

## 1. 与 design baseline v3 的分工

- **v3**：角色选择首页、loading、点阵角色展示模式等与 **页面壳层** 相关的基线。
- **v4**：玩家点击「进入游戏」之后见到的 **新手村场景**——地图尺度、地表表现、HUD 与渲染优化。

二者叠加构成 Pixel Knight 当前「从选角到进村」的视觉与交互连续体，但不互相顶替文档职责。

## 2. 与 dev log（v1）的关系

迷宫探索、撤离、掉落等 **局内闭环** 仍以 [`pixel-knight-dev-log-2026-04-21-v1.md`](../pixel-knight-dev-log-2026-04-21-v1.md) 的记录为准。

若日后编写 **像素骑士 dev log 第 3 版**，应聚焦于该文档未覆盖的新增系统版本（例如副本、职业、存档大改），而不是把设计基线内容重复成 dev log；**本篇 v4 是设计基线，不是 dev log v3。**

## 3. 裁边与 portal 修正

- 裁边的动机是去掉「无建筑的纯草地条带」，让相机与构图落在核心区。
- 历史上 `starterVillage.portal` 曾与格点 **`P`** 不一致；v4 将 `portal` **与地图上 `P` 格及 hotspot 对齐**，保证小地图与 HUD 语义统一。

## 4. 装饰层移除

- 曾考虑在村庄铺额外装饰（小物件、切片拼贴等）；v4 选择 **不渲染装饰层**，降低绘制与数据维护成本。
- 地标建筑（shop、portal、铁匠等）仍通过 landmark 层绘制；交互仍通过 hotspot。

## 5. HUD 与地表缓存

- **HUD**：村庄阶段若每帧 `onHud`，会与 React 组合产生不必要更新；采用 **home 状态签名** 相等则跳过。
- **地表缓存**：草地 + 砖路 patch 在首帧合成到离屏画布，后续按视口拷贝，减少每帧重复 pattern/绘制；地图或阶段变化时失效缓存。

## 6. 后续可选方向

- 纵向再次裁切或调整 `VILLAGE_ROWS`，需同步道路、地标 footprint 与 patch 包围盒。
- 环境音、传送门反馈、未引用素材清理等，独立成专项，不阻塞 v4 基线冻结。
