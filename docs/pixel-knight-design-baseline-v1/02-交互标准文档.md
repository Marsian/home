# Pixel Knight 前期交互标准文档 v1

日期：2026-04-22  
适用范围：PC 键鼠优先，手柄为附录兼容  
覆盖场景：角色选择、村庄、背包 / 状态

## 1. 文档目标

本文件定义 Pixel Knight 首发阶段的统一交互语法。目标不是写完整功能说明，而是保证后续 UI 实现、交互动效、输入映射、信息密度和窗口逻辑保持一致。

## 2. 交互总原则

- 鼠标悬停负责解释，点击负责决策
- 高频功能优先一跳可达，但保留 NPC 或场景语义外壳
- 所有窗口均遵循“可读优先、比较优先、关闭可预期”
- 同类操作在不同场景中使用同一按键和同一反馈节奏
- 首版默认 PC，触屏仅预留改造点，不做强约束

## 3. 全局输入约定

### 3.1 键鼠主映射

- `ESC`：关闭当前最上层窗口；若无窗口则返回上级
- `Enter`：确认当前主操作
- `Tab`：打开或关闭角色 / 背包主面板
- `左键单击`：选中、查看、切换焦点
- `左键双击`：快速确认、装备、进入
- `右键`：打开快捷动作菜单
- `鼠标悬停`：显示解释、详情、对比、热区提示
- `滚轮`：滚动列表、分页区、说明区

### 3.2 手柄兼容附录口径

- `B / Circle` 对应 `ESC`
- `A / Cross` 对应 `Enter / 左键确认`
- `Y / Triangle` 对应快捷动作
- `LB / RB` 切页
- 左摇杆移动焦点，右摇杆负责说明区滚动

## 4. 信息层级规则

### 4.1 固定层级

每个正式窗口都必须包含以下层级：

1. 标题区
2. 当前层级或页签区
3. 主内容区
4. 主操作按钮
5. 次操作按钮
6. 关闭入口

### 4.2 信息优先级

- 一级：当前决策必须信息，例如职业定位、装备收益、NPC 功能名
- 二级：帮助比较的信息，例如主属性倾向、稀有度、强化层级、词条说明
- 三级：补充解释和叙事文本，例如短对话、世界观 flavor text

## 5. 窗口打开与关闭逻辑

### 5.1 打开逻辑

- 从场景内触发时，先出现轻量提示，再进入正式窗口
- 从主菜单或快捷键触发时，直接打开该窗口的默认页
- 同一时间只允许一个全屏级主窗口占主焦点
- 子弹窗只能叠在主窗口之上，不可脱离根窗口独立存在

### 5.2 关闭逻辑

- `ESC` 永远关闭最上层
- 若存在未保存输入，关闭前给出一次确认
- 二级弹窗关闭后，焦点返回打开它的组件
- 从 NPC 打开的窗口关闭后，回到村庄并保留 NPC 朝向与最近交互对象

## 6. 焦点流规则

### 6.1 通用焦点顺序

1. 标题 / 页签
2. 左上主信息块
3. 主列表或主网格
4. 右侧详情
5. 主按钮
6. 次按钮
7. 关闭入口

### 6.2 鼠标与键盘共存

- 鼠标进入某区域后，键盘焦点可被该区域接管
- 若刚完成双击装备等动作，焦点停留在结果对象或对应槽位
- 页面切换后默认回到新页的一级内容，而不是保留在旧按钮

## 7. 三段式反馈节奏

所有高频交互必须具备三级反馈：

### 7.1 可操作前提示

- 悬停文字
- 地面交互标记
- 按钮高亮
- 装备可替换箭头

### 7.2 操作中反馈

- 按钮按下态
- NPC 对话气泡
- 拖拽跟手
- 处理中转圈或短时锁定

### 7.3 操作后确认

- 结果 toast
- 槽位变化
- 数值涨跌色
- 新页签切换完成

## 8. 数值展示规则

### 8.1 分类

所有数值面板必须区分：

- 永久属性
- 装备增益
- 临时增益

### 8.2 表达方式

- 永久属性：常规亮度
- 装备增益：右侧附带来源标签
- 临时增益：加色高亮并附剩余时间或状态说明
- 比较逻辑：正向变化用上箭头和暖绿，负向变化用下箭头和赭红

## 9. 三个重点场景交互原则

### 9.1 单角色入口页

- 页面默认展示唯一角色，不提供创建和切换
- 悬停当前角色信息区显示职业细节
- 单击主按钮或按 `Enter` 进入游戏
- `ESC` 返回上级
- 页面不承载名字输入、外观选择、赛季选择

### 9.2 村庄

- 玩家靠近 NPC、告示牌、传送点、仓库类物件时显示简短提示
- 点击 NPC 先触发一句短对话，再打开对应界面
- 高频功能支持“再次点击直达子页”，但首次进入保留 NPC 壳
- 村庄不承担复杂弹窗堆叠；优先跳转到系统窗口

### 9.3 背包 / 状态

- 单击查看详情
- 双击或拖拽装备
- 右键打开快捷动作
- 状态页与背包页使用同一总窗口骨架
- 后续扩展项如 `Shift` 批量操作在本版只预留，不作为首版硬规范

## 10. 提示密度规则

- 一个区域同一时间只展示一个主提示
- 物品详情优先展示结果导向内容，不先堆背景说明
- 村庄内常驻提示只留最关键的入口语义
- 新手引导文字不覆盖主交互热点

## 11. 组件级规范

### 11.1 `UiComponentSpec`

```ts
type UiComponentSpec = {
  component_id: string
  purpose: string
  pixel_size: { width: number; height: number }
  states: string[]
  text_rules: string[]
  input_rules: string[]
}
```

### 11.2 常用组件状态

- 按钮：`default / hover / pressed / disabled`
- 页签：`default / hover / active / locked`
- 物品格：`empty / occupied / hover / selected / compare / equipable`
- NPC 热点：`idle / nearby / interact / cooldown`

## 12. 异常态处理

- 单角色数据缺失：禁止进入，并给出短提示
- 背包已满：阻止继续放入，提供去向建议
- 装备不可用：禁用主按钮，说明原因
- 网络或存档失败：保留当前界面，给重试入口，不直接踢出
- NPC 功能未开放：保留人物和短对话，窗口内用锁定态说明

## 13. 移动端改造预留

- 单角色入口页预留更大的主按钮点击区
- 村庄热点密度在移动端需要合并提示层
- 背包三栏改为上下或两步式切换，但语义结构不变
- 右键快捷动作需要转换为长按

## 14. 验收口径

- `ESC`、`Tab`、`Enter` 在三大场景中的行为是否完全可预期
- 悬停、点击、确认是否在所有窗口维持统一节奏
- 同类按钮、弹窗、关闭入口是否不需要额外学习
- 数值对比是否始终区分永久 / 装备 / 临时三类来源
