# Pixel Knight 前期场景规格文档 v1

日期：2026-04-22  
覆盖场景：角色选择、村庄、背包 / 状态  
适用平台：PC 优先

## 1. 文档目标

本文件将三大重点场景拆为可实现的结构规格。每个场景统一包含：

- 场景目标
- 布局
- 组件清单
- 状态切换
- 入口 / 出口
- 异常态

## 3. 场景一：单角色入口界面

### 3.1 目标

- 作为首发阶段的单角色进入页
- 让玩家用最短路径完成“查看当前角色并进入游戏”
- 只保留当前角色的必要信息，不承载角色创建、职业切换、赛季分流

### 3.2 布局

固定四区：

1. 角色立绘区
2. 当前角色信息区
3. 基础说明区
4. 确认入口区

PC 推荐布局：

- 左侧 `42%`：角色立绘、待机展示、世界背景
- 中部 `26%`：当前角色卡、等级、职业、进度概览
- 右侧 `32%`：职业简介、主属性倾向、起始武器、战斗定位
- 底部或右下：进入游戏按钮和返回入口

### 3.3 组件清单

- 场景标题
- 角色立绘框
- 当前角色卡
- 当前角色名
- 当前等级
- 当前进度概览
- 职业简介文本
- 主属性徽记
- 起始武器展示
- 战斗定位标签
- 进入游戏按钮
- 返回按钮

### 3.4 必须支持

- 单个固定角色展示
- 当前角色名
- 当前等级 / 基础进度
- 职业简介
- 主属性倾向
- 起始武器 / 战斗定位
- 进入游戏

### 3.5 状态切换

- `default`：默认展示当前唯一角色
- `hover-enter`：进入按钮高亮
- `focus-summary`：当前角色信息区聚焦，右侧展示固定说明
- `confirm-enter`：按下进入游戏，进入加载或村庄
- `returning`：退出到上一级

### 3.6 入口 / 出口

- 入口：主菜单“开始游戏”
- 出口：
  - 进入村庄出生点或继续点
  - 返回上级

### 3.7 异常态

- 当前角色数据缺失
- 当前角色资源未加载完成
- 存档写入失败

### 3.8 实现约束

- 不加入角色创建、角色删除、赛季入口、充值入口
- 当前角色卡、属性徽记、确认按钮采用同类语义不同画法
- 不直接复刻原作职业像素形象

## 4. 场景二：村庄界面

### 4.1 目标

- 作为首发主 Hub，承接高频系统和轻任务
- 让玩家在低认知负担下找到 NPC 与系统入口
- 保持“功能密集但不拥挤”的流线

### 4.2 布局

首版采用固定主视图，推荐自下向上进入主街。

核心区域：

1. 出生点与视角落点
2. 主路网
3. 左右建筑立面
4. 功能 NPC 站位
5. 世界 / 副本入口
6. 邮箱 / 公告 / 传送类静态物件

布局原则：

- 玩家出生点在画面下方偏中
- 第一视线内必须看到公告物、商店、至少一个升级或打造类 NPC
- 主路最窄可通行宽度不低于 2.5 个角色身位
- 高频 NPC 围绕主街布置，低频入口放在二层路径或边缘节点

### 4.3 组件清单

- 村庄标题或区域名
- 主路地砖
- 房屋立面
- 门牌 / 招牌
- 功能 NPC
- 交互光点
- 世界地图 / 副本入口
- 邮箱
- 公告板
- 仓库或仓储物件
- 传送类静态物件
- 轻任务气泡

### 4.4 首版系统承载范围

- 功能 NPC
- 世界 / 副本入口
- 仓库 / 打造 / 商店 / 洗点等高频系统
- 基础引导与轻量任务承接

### 4.5 NPC 组织建议

依据公开资料可借鉴的秋梨村组织方式，首版建议至少预留：

- 铁匠 / 强化
- 商店
- 仓库
- 卡片或材料相关商人
- 洗点商人
- 宝石或镶嵌相关商人
- 引导 / 世界入口相关 NPC

### 4.6 状态切换

- `idle`：仅显示场景本体
- `nearby-hotspot`：靠近热点出现简短提示
- `npc-hover`：NPC 轮廓提亮
- `npc-dialog`：显示一句短对话
- `system-opening`：切入对应系统窗口
- `return-from-window`：返回村庄并恢复最近视角

### 4.7 入口 / 出口

- 入口：角色创建完成、关卡结算返回、登录后继续
- 出口：
  - 进入系统窗口
  - 进入副本 / 世界地图
  - 返回主菜单

### 4.8 异常态

- NPC 功能未解锁
- 当前任务阻断某入口
- 临时系统关闭或未开放
- 返回村庄时背包已满或邮件待领取

### 4.9 实现约束

- 不设计活动广场或节庆 UI 区
- 高频功能入口允许二次直达，但保留 NPC 语义壳
- 门牌 / 招牌 / 光点必须在 1 秒内让玩家看懂功能类别

## 5. 场景三：背包 / 状态界面

### 5.1 目标

- 提供装备管理
- 提供属性查看
- 聚合成长相关入口
- 保持与状态页共用同一视觉系统

### 5.2 布局

固定三列并列层：

1. 左侧：角色纸娃娃 / 装备槽
2. 中间：背包分页与物品格
3. 右侧：属性 / 词条 / 说明面板

推荐宽度：

- 左列 `28%`
- 中列 `38%`
- 右列 `34%`

### 5.3 组件清单

- 主窗口标题
- 页签区：背包 / 状态
- 纸娃娃角色
- 装备槽
- 强化入口
- 背包分页栏
- 物品格网格
- 物品详情卡
- 基础属性列表
- 派生属性列表
- 羁绊 / 词条入口
- 主操作按钮
- 次操作按钮

### 5.4 必须支持对象范围

- 武器、护甲、饰品、材料、消耗品、任务物
- 装备品质层级
- 强化 / 词条 / 羁绊类信息入口
- 角色基础属性与派生属性

### 5.5 状态切换

- `bag-default`：打开到最近使用分页
- `status-default`：打开到属性页
- `item-hover`：右侧刷新详情
- `compare`：装备中物品与候选物品对比
- `dragging`：拖拽物品
- `context-menu`：右键动作展开
- `upgrade-entry`：跳转强化或词条窗口

### 5.6 入口 / 出口

- 入口：
  - `Tab`
  - 村庄 NPC
  - 掉落结算后快捷查看
- 出口：
  - `ESC`
  - 顶部关闭按钮
  - 返回村庄

### 5.7 异常态

- 背包已满
- 装备条件不满足
- 目标槽位不可装备
- 物品锁定
- 详情数据缺失

### 5.8 实现约束

- 单击查看详情
- 双击或拖拽装备
- 右键打开快捷动作
- 状态页与背包页保持同一总窗口骨架
- 不做活动背包、赛季背包、限定分页

## 6. 跨场景统一语法

- 标题条样式共享
- 关闭入口位置共享
- 主按钮色阶共享
- 标签页语法共享
- 提示框与确认窗共享
- 稀有度颜色与数值比较颜色共享

## 7. 验收口径

- 仅根据本文件，是否能画出三张结构一致的线框稿
- 实现团队是否能直接拆出组件、状态、入口与异常态
- 三个场景之间是否共享同一 UI 语法，而非三套独立风格
