# Pixel Knight 前期美术标准文档 v1

日期：2026-04-22  
适用范围：`pixel-knight` Web 首发前期规范  
覆盖场景：角色选择、村庄、背包 / 状态  
强约束：不纳入活动界面、赛季入口、运营入口

## 1. 文档目标

本文件用于给 Pixel Knight 首发阶段建立统一的像素美术基线，使界面设计、像素角色、场景搭建、图标制作和后续资源命名使用同一套语言。

当前项目只有玩法骨架，尚无正式素材包；因此本版标准优先解决三件事：

- 统一像素栅格、轮廓、色板、明暗和材质规则
- 统一角色、场景、窗口、物品、图标之间的风格边界
- 明确哪些内容允许高度参考《元气骑士前传》，哪些必须改写以形成 Pixel Knight 的可区分表达

## 2. 总体视觉方向

### 2.1 风格定位

- 核心气质：暖色手工像素奇幻、轻冒险、低压但密集功能组织
- 参考对象：以《元气骑士前传》的公开画面信息架构和像素节奏为主
- 项目要求：首轮允许内部验证阶段做强参考；对外可见稿必须保证 UI 外框、职业识别图形、图标底板、NPC 形象可区分

### 2.2 画面关键词

- 圆钝而清晰的轮廓
- 明亮但不刺眼的高饱和点缀
- 木、石、布、铜、暖灯的中世纪轻奇幻材质
- 低透视、正侧混合、便于点击和阅读
- 功能密集但不过分写实

## 3. 统一栅格与分辨率规则

### 3.1 基础栅格

- 基础像素单位：`1x`
- 资产绘制建议基格：`16x16`、`24x24`、`32x32`、`48x48`
- UI 基础模数：以 `8px` 为排布步长，以 `2px` 为修正单位
- 视口基准：PC 概念稿按 `1600 x 900` 输出
- 渲染要求：所有像素图必须使用整数缩放，不允许出现亚像素模糊

### 3.2 镜头与透视

- 角色与 NPC：3/4 俯视偏正面，支持 8 向或 4 向扩展
- 建筑：2.5D 低透视，正立面信息优先，不做强透视拉伸
- UI：正投影视图，不使用拟真倾斜面板
- 地面交互点：使用俯视图标或地面闪烁光斑，不使用悬浮 3D 箭头

## 4. 六类视觉规则

### 4.1 角色规则

- 头身比：首发统一按 `1 : 1.35` 到 `1 : 1.5` 的 Q 版比例控制
- 待机姿态：身体正立，重心略前，武器朝向与主手一致
- 朝向组：先规范正下、左下、右下、正上四组；后续扩到八向时沿同一骨架延展
- 轮廓粗细：外轮廓以 `1px` 深色描边为主，关键识别点允许局部 `2px` 加粗
- 武器握持：近战武器柄长不超过角色身高的 `0.8`；远程武器不遮挡头部主轮廓
- 职业识别：靠武器轮廓、肩颈配件、头饰、披风或法器完成识别，不依赖复杂细节
- 禁止项：直接复刻原作基础职业像素形象、发型剪影、配色分布和武器轮廓

### 4.2 界面规则

- 窗口外框：木框或铜框语义，外边 `2px` 深描边，内衬为浅暖色石板或布面
- 标题条：固定高对比色带，左侧标题、右侧关闭入口
- 标签页：矩形切角，不使用原作同款页签轮廓
- 按钮：主按钮更高饱和，次按钮偏中性；默认高度遵循 `24px / 32px / 40px`
- 滚动条：窄轨道 + 方头滑块，不用玻璃、荧光、极细线样式
- 数值条：生命 / 经验 / 强化进度统一使用粗颗粒块面
- 图标底板：统一圆角切角底，不直接复刻原作卡框和底托

### 4.3 物品规则

- 武器：轮廓优先于内部纹理，先看得出长短、单双手和攻击方式
- 防具：用肩、胸、腕、足四个高识别块面控制套装感
- 饰品：以轮廓和点缀材质体现差异，避免尺寸过小失真
- 材料：必须保证单色剪影可辨认，优先石头、矿片、叶片、符文、骨片等简单形
- 消耗品：瓶、卷轴、果实、包裹四类基础语义固定
- 稀有度发光：只允许 `legendary / set` 使用明显外发光；`common / magic / rare` 仅用描边和色相区分

### 4.4 场景规则

- 地砖：基础地砖 `16x16`，允许 `32x32` 作为组合模块
- 建筑：立面信息优先，屋檐和门牌形成主识别点
- 植被：必须服从主路网，不能侵占交互路径宽度
- 灯光：仅在门口、商铺、传送物、公告物周边集中使用
- 摊位：统一面对主路开口，避免背向入口
- 公告物与邮箱：必须是高频静态语义点，放在出生点第一视线内

### 4.5 反馈规则

- 选中：深色描边 + 内侧高亮边
- 悬停：整体提亮 `8%` 到 `12%`，并出现小幅暖色浮光
- 可交互：以低频闪烁或脚底光圈提示，不用夸张脉冲
- 获得物品：图标上浮 + 稀有度色闪
- 装备替换：槽位亮起，对比箭头和数值增减颜色同时出现
- 数值变化：上升为暖绿，下跌为赭红，临时增益为琥珀金

### 4.6 文本规则

- 中文字号阶梯：`12 / 14 / 16 / 20 / 24 / 32`
- 标题字重：粗黑；正文和数值用中黑或常规
- 字体策略：优先像素风中文标题字，正文可退回项目现有中文字体
- 数值对齐：右对齐或按小数点对齐；同列不混排
- 稀有度颜色映射：
  - 普通：`#d9d0bb`
  - 魔法：`#6cc6ff`
  - 稀有：`#8e79ff`
  - 传奇：`#ffb347`
  - 套装：`#6ce3a1`

## 5. 明暗与材质语言

### 5.1 明暗分层

- 单体资产采用 `3` 到 `5` 层明暗
- 金属材质允许增加锐利高光点，但不超过 `2` 个主高光面
- 布料和木材采用软过渡块面，不用高镜面
- 场景块面先做大明暗，再补纹理；禁止先堆细纹再找体积

### 5.2 材质词典

- 木：暖褐主色 + 稍偏红暗部，纹理横向或斜向稀疏分布
- 石：黄灰或青灰，边缘轻损耗，避免纯灰
- 铜铁：高对比边缘 + 小面积锈点或磨损
- 布皮：低反光、柔和折面，用色块分面代替细褶皱
- 魔法能量：只用于技能、传送、强化、高稀有装备，不可泛滥

## 6. 推荐色板区间

### 6.1 全局中性色

- 深描边：`#2d2218`
- 次深描边：`#4a392a`
- 窗口浅底：`#e7d8bc`
- 纸面浅底：`#f1e6cf`
- 木框主色：`#8a5f38`
- 铜饰主色：`#c48e42`

### 6.2 场景主题色

- 村庄主色：麦黄、木棕、叶绿、暖橙灯火
- 角色选择主色：米白、藏青、旧金、酒红强调
- 背包 / 状态主色：羊皮纸黄、深木棕、青铜绿、稀有度高亮色

## 7. 复刻与改写边界

### 7.1 允许强参考

- 信息架构
- NPC 功能组织逻辑
- 窗口大分区思路
- 村庄 Hub 的“主路 + 功能点”布局方法
- 背包 / 状态三栏式信息组织

### 7.2 必须改写

- 角色职业卡外框
- 属性徽记图形
- 确认弹窗外框
- 背包格底板与槽位切角
- NPC 角色造型、发型、服饰块面
- 村庄门牌和招牌图形

### 7.3 禁止直接复刻

- 原作职业像素角色成品
- 原作界面整套卡框、图标、按钮贴图
- 原作招牌文案、商店牌面、独有图标资产
- 原作完整村庄截图拼贴

## 8. 文档 Schema

### 8.1 `ArtAssetSpec`

```ts
type ArtAssetSpec = {
  asset_family: string
  grid: '16x16' | '24x24' | '32x32' | '48x48'
  palette_group: string
  silhouette_rules: string[]
  reuse_policy: '保留' | '改写' | '舍弃' | '禁止直接复刻'
}
```

### 8.2 资产家族建议

- `ui-window`
- `ui-button`
- `ui-tab`
- `ui-iconplate`
- `character-base`
- `npc-service`
- `village-building`
- `item-weapon`
- `item-armor`
- `item-material`

## 9. 验收口径

- 不同美术按本文件绘制的按钮、标签页、装备图标能否自然归为一套体系
- 同一职业的站姿、武器识别、头身比例是否保持一致
- 村庄建筑、NPC、招牌、交互点是否在远视距下也能被快速识别
- 背包和状态页是否共享统一窗口语言，而不是两个独立皮肤
