# 迭代决策记录

日期：2026-04-27

## 1. 从效果图到实现

v2 的第三版概念稿确定了角色选择首页方向：简洁像素背景、右侧角色列表、中央角色展示、进入游戏按钮与角色展示绑定。本轮 v3 将该方向落地到真实页面。

关键实现决策：

- 不再用 CSS 绘制主要 UI 框体，改用 PNG 静态素材。
- 文本仍由前端渲染，避免固定文字烘焙进素材。
- 角色仍由点阵角色系统实时渲染，不使用概念稿里的静态角色图。

## 2. 素材处理

本轮先生成和清理整套组件素材，再切分为独立资源。组件素材清理目标：

- 透明背景。
- 黑色像素描边边缘干净。
- 去掉白边、灰边和深灰毛边。
- 独立组件方便后续引用和替换。

背景素材单独重新生成，要求没有顶部 banner 或任何 UI 元素。

## 3. 功能边界

角色选择页当前只承担“选择已有角色并进入游戏”：

- 没有游戏内返回入口。
- 保留页面原本外层的标题和导航。
- 不展示职业介绍。
- 不展示子职业。
- 不展示“新兵”等额外标签。
- 不渲染不存在的游侠、法师角色，使用空卡片占位。

## 4. 角色列表头像

曾尝试只截取头部，但效果不自然。最终采用：

- 在头像框内渲染完整点阵角色。
- 使用较大的统一 pixelSize。
- 通过头像框裁切，只露出偏头部区域。
- 角色整体向下放置，给头盔预留空间。
- 使用 `static` mode，头像完全静止。

## 5. 中央角色

中央角色最终保持 `idle`，而不是 `static`。但页面层不能移动脚底锚点，否则腿部会随呼吸移动，造成漂浮感。

最终规则：

- idle 动效由 renderer 内部控制。
- 页面层 `actorFeetY` 固定。
- canvas 按正方形比例显示，不能非等比拉伸。

## 6. Loading 页面

loading 页面应当和角色选择页使用同一背景定位。最初只替换了背景图，但父容器比例仍是 `16/10`，导致同一张图被不同裁切。

最终规则：

- loading/error/character select 都使用 `1672/941` 画幅。
- 背景图 class 与角色选择页一致。
- loading 面板保留暗化层和进度反馈。

## 7. 当前后续事项

- 若未来增加真实角色存档，应把 `characterSelectEntries` 接入 profile/save 数据，而不是硬编码。
- 若未来开放新职业，空卡片可替换为真实角色列表项。
- 若未来增加装备外观，需要从角色数据读取，不能在选择页中硬编码给角色穿戴不存在的装备。
- 视觉回归时应重点检查：背景裁切、中央角色比例、角色脚底是否漂浮、右侧列表与 banner 的右侧关系。
