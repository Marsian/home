# 迭代决策记录

日期：2026-04-29

## 1. “全屏”的语义

Pixel Knight 语境下的“全屏”统一指**游戏容器内全屏**，不指页面级或浏览器级全屏。

因此背包 overlay 必须只覆盖游戏画面区域，页面标题、站点导航与浏览器视口不属于背包遮罩范围。

## 2. HUD 状态框采用双层框

单张状态框无法同时满足“条体填满槽位”和“框体压在条体上方”的视觉要求，因此 v5 将左上状态框拆为底图与前景框：

- 底图提供整体面板与槽位背景。
- HP / MP fill 放在中间层。
- 前景框覆盖条体边缘，保留斜角槽位与像素边框。

蓝条与红条槽位应视觉一致；后续若重新生成状态框，必须同步验证满值与非满值截图。

## 3. 小地图采用“地图在下，框在上”

小地图与框体画风割裂的主要原因不是地图逻辑，而是层级与窗口填充：

- 实时地图 SVG 必须填满 frame 的透明窗口。
- frame 必须覆盖在地图之上。
- 内容不足时允许使用背景色补齐窗口。

## 4. 背包只保留核心 RPG 元素

参考图中的冗余页签、复杂按钮与多套装备栏不进入 v5。当前背包只保留：

- 单套装备槽。
- 中央角色预览。
- 底部统计值。
- 右侧 6×6 背包格。
- hover 详情与点击装备/卸下。

角色下方展示台因遮挡与截断风险移除。

## 5. 装备 catalog 不虚构

v5 明确不再生成没有点阵 JSON 的装备。历史上的手套、靴子、两枚戒指、虚构武器名或虚构盾牌名都从掉落路径中移除。

保留项链与戒指空槽是为了 UI 结构完整，但在没有真实资源前不生成对应物品，也不承诺显示在角色身上。

## 6. 主手 / 副手优先于武器 / 盾牌

当前代码语义按 `mainHand` / `offHand` 管理装备，不按 `weapon` / `shield` 管理。v5 迁移历史 starter sword/shield，并在存档 normalize 时处理旧字段。

## 7. 角色外观必须来自同一份装备数据

背包角色、村庄角色、副本角色不能各自使用固定假装备。v5 将 `profile.equipment` 解析为点阵装备映射后同步给游戏引擎，确保装备变更即时反映到各个角色渲染场景。

## 8. 验收方式

本轮细节主要通过浏览器截图验收，包括：

- 左上 HUD 条体满值、非满值与缩放。
- 小地图填充与右上背包按钮对齐。
- 背包装备槽、6×6 grid、tooltip、卸下逻辑。
- 统计区与角色/装备槽对齐，以及大屏响应式字号。

后续若调整 HUD mask、背包槽位或统计区位置，应先截图测量，再改 CSS 或素材，不再仅凭视觉估算。
